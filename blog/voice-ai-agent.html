Your First Voice AI Agent: What Actually Happens on the Call

Neolith Team · November 4, 2026 · 3 min read

A voice agent is not a chatbot with a microphone. The hard part is not the language model — it is everything that has to happen inside the pause between two sentences.

Most teams start a voice agent project by writing a personality prompt. That is the least important decision they will make. What decides whether callers hang up satisfied is whether the system can hear, decide and speak again fast enough to feel like a conversation — and whether it knows when to stop guessing and hand over to a person.

The loop, in plain terms

Every voice agent is the same four-stage loop, repeated until the call ends:

  • Transcribe. Streaming speech-to-text turns audio into words as they are spoken. This stage is where accents, background noise and phone-line compression do their damage.
  • Decide. The language model receives the transcript, the conversation so far and, crucially, a set of tools it is allowed to call — look up availability, create a booking, check an order.
  • Act. Tool calls hit your real systems. This is the moment the agent stops being a demo and starts touching production data, which is why permissions, validation and idempotency matter here more than anywhere else.
  • Speak. Text-to-speech streams audio back, ideally starting on the first clause rather than waiting for the full sentence.

Latency is the whole game

People tolerate a surprising amount of confusion in a voice interface. They do not tolerate silence. If the gap between the caller finishing and the agent responding drifts past roughly a second, callers assume the line dropped: they say "hello?" and talk over the answer.

You buy that time back in three places. Stream every stage instead of batching it. Keep the model small and fast for routing, and reserve the expensive model for the turns that need judgement. And skip the language model entirely for the genuinely fixed turns — an opening greeting does not need inference.

Interruption handling is not a nice-to-have

Real callers interrupt, correct themselves mid-sentence, and answer before you finish asking. An agent that keeps talking over an interruption feels broken instantly, in a way that no amount of prompt tuning will fix. Barge-in detection — noticing speech while the agent is speaking, stopping playback, and discarding the now-stale half-sentence the agent had planned — is a core capability, not an enhancement.

Tools decide what the agent can actually do

A voice agent with no tools can chat pleasantly and accomplish nothing. The useful ones are narrow and boring: check a calendar, create an appointment, look up a record, escalate. Two rules save a lot of pain. First, every tool needs a failure path the agent can speak out loud, because "the system is unavailable" said calmly is fine and a silent retry loop is not. Second, the outcome should be written down in a structured form — after the call, a machine-readable record of what was decided — so the conversation produces data your team can act on rather than a transcript nobody reads.

Design the handoff before the happy path

The best voice agents are explicit about their limits. Define the intents that must reach a human — complaints, anything medical or financial, a caller who asks twice — and make escalation a first-class tool rather than a fallback. Then route those calls with the context already gathered, so the person picking up does not start from "how can I help you today?".

Test with transcripts, not vibes

Listen to real calls and score them the way you would score any system: task completion, turns to resolution, how often the agent asked for something the caller had already said. Two or three patterns usually account for most bad calls.

When not to build one

If the interaction needs deep negotiation, or if a form would do, a voice agent is an expensive way to frustrate people. Voice earns its place when the caller cannot easily use a screen — on the road, on a warehouse floor, mid-shift — and when the task is bounded enough that a well-tooled agent can finish it.
